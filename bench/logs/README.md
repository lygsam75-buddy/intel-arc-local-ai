# `bench/logs/` —— 原始运行日志（**不随仓库分发**）

## 当前状态

**这个目录只放说明，不放日志正文。** 约 430 个原始文件（39 MB，`llama-server` stdout 重定向 +
功耗采样 `.csv` / `.meta.json` / `.stop`）保留在**本机归档**，公开仓库不包含它们。

**为什么移出**：它们是**过程记录**，不是定稿内容。结论、判据、装载形态都已经提炼进
`docs/` 与 `bench/data/` 的结构化记录里；把几百个机器输出文件摊在仓库首页，读者看不出
哪份是结论、哪份是中间产物。需要复核某个具体判据时，按下面的命名规范在本机归档里定位。

**取原始日志**：在仓库 issue 里说明要哪一批（日期 + 卡 + 任务），我们把对应文件贴出来。

---

## 命名规范（归档与本仓库一致）

| 前缀 | 含义 |
|---|---|
| `2026-10-16_…` | 按日期的正式批次：`<日期>_<卡>-<显存>_<量化/模型>_<变体>.log` |
| `pwmulti_…` | 功耗多档扫描：`pwmulti_<卡>-<任务>-<分辨率>-d<秒数>-<变体>.{csv,meta.json,stop}` |
| `b1_…` / `b2_…` | 槽位对照（主槽 / 副槽）的分档日志 |
| `ctxcap_…` | 上下文容量扫描 |

`.csv` 是每秒采样的功耗原始表（列：`t,iso,dom,w,e_uj,dt_sec`），
`.meta.json` 是同批的配置与判读字段，`.stop` 是采样停止标记（0 字节）。

---

## 路径归一化（如果要把某份日志贴出来）

公开发布任何日志前，必须做一次**本机绝对路径归一化**：

| 日志里原本的 | 应写作 |
|---|---|
| `\LLM\models\…`（带盘符，正/反斜杠两种写法都有） | `<模型目录>/…` |
| `\LLM\llama.cpp\build\bin\…` | `<llama.cpp>/build/bin\…` |
| 仓库内的 `bench/data`、`bench/logs` 绝对路径 | `bench/data`、`bench/logs` |

左列只保留**目录名与结构**，盘符与上级目录省略。归一化只动路径字符串，
其余字节逐字节保持不变——包括时间戳、功耗读数、报错行。

验证方式：同一套替换规则施加到原件上，结果与待发布文件**逐字节相等**。
